# AnimalVision — Build From Scratch

Build a complete, clean, working **AnimalVision** animal-classification web application from scratch.

The project must be designed to work on **Android using Acode + Termux**, with Python running the local web server and TensorFlow doing the training. Do not assume a desktop IDE, Node.js build system, React, Vite, npm, or Docker.

The final project must be simple enough to edit directly in Acode.

## Goal

AnimalVision is an animal image classifier.

It must:

1. Train a CNN locally from an image-folder dataset.
2. Save the trained model.
3. Convert the trained model into a browser-compatible TensorFlow.js model.
4. Run the model directly in the browser.
5. Allow the user to upload or drag/drop an image.
6. Resize the image to exactly **64×64** before inference.
7. Display the predicted animal and confidence.
8. Display the top 5 predictions.
9. Have a separate OpenRouter mode.
10. Have a clean dark UI.
11. Work entirely from a simple Python server.
12. Be easy to modify in Acode.

# Training

Create `train.py`.

Use TensorFlow/Keras.

Use a small CNN suitable for a low-resource Android device.

Input:

```text
64 × 64 × 3
```

Output:

```text
15 classes
```

Use:

* Rescaling 1/255
* Conv2D
* BatchNormalization
* MaxPooling
* GlobalAveragePooling
* Dense
* Dropout
* Softmax

Use:

```text
sparse_categorical_crossentropy
```

Use Adam.

Use validation split.

Use data augmentation:

* horizontal flip
* small rotation
* small zoom
* small contrast adjustment

Do NOT use excessive augmentation.

# IMPORTANT TRAINING VALIDATION

The training script must actively detect broken training.

Before training, print:

```text
Class distribution
```

showing the number of images in every class.

If a class contains zero images, stop with a clear error.

Calculate class weights automatically to reduce the effect of dataset imbalance.

During training, print:

* training accuracy
* validation accuracy
* training loss
* validation loss

Use:

* ModelCheckpoint
* EarlyStopping
* ReduceLROnPlateau

After training, evaluate the validation set.

Then perform a prediction-distribution test.

Print something like:

```text
Prediction distribution:

bear: 12
cat: 15
deer: 10
dog: 13
...
tiger: 14
...
zebra: 11
```

If almost every validation image is predicted as one class, print a large warning:

```text

Check dataset quality and training.
```

Do not silently declare training successful.

# Model Conversion

Create `convert.py`.

The training model must first be saved as:

```text
models/animal_model.keras
```

Then convert it into a **browser-compatible TensorFlow.js model**.

The browser uses:

```javascript
tf.loadLayersModel(
    "/model/web_model/model.json"
)
```

Do NOT use `loadGraphModel()`.

The converter must produce:

```text
model/web_model/model.json
model/web_model/*.bin
model/web_model/classes.json
```

Copy the exact `models/classes.json` into `model/web_model/classes.json`.

The conversion process must verify that:

1. `model.json` exists.
2. weight files exist.
3. `classes.json` exists.
4. the model can be loaded using TensorFlow.js-compatible format.
5. the input shape is `[null, 64, 64, 3]`.
6. the output contains 15 classes.

Avoid Keras 3 / TensorFlow.js incompatibilities.

If the installed TensorFlow.js converter cannot correctly convert the Keras model, provide a compatible conversion route rather than producing a broken `model.json`.

Do not generate a GraphDef model when the browser code expects a Layers Model.

# Browser Model Preprocessing

The browser must use exactly the same preprocessing as training.

Before inference:

1. Load the uploaded image.
2. Draw it to a canvas.
3. Resize it to exactly:

```text
64 × 64
```

4. Convert pixels to float32.
5. Normalize using:

```text
pixel / 255
```

6. Add the batch dimension.

Final tensor:

```text
[1, 64, 64, 3]
```

Do not use a different normalization method.

# OpenRouter Mode

Create a separate toggle/button:

```text
My Model
OpenRouter
```

OpenRouter must NOT interfere with the local model.

The server should handle OpenRouter requests.

Do NOT put an OpenRouter API key directly into frontend JavaScript.

Use an environment variable:

```text
OPENROUTER_API_KEY
```

The Python server should read it from the environment.

If the key is missing, show:

```text
OpenRouter is not configured.
Set OPENROUTER_API_KEY in the environment.
```

Do not crash the entire application.

Use a current free vision-capable OpenRouter model when configured, but make the model name a configuration value instead of hardcoding it throughout the application.

Example:

```text
OPENROUTER_MODEL
```
